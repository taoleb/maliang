# Tech Daily Brief（技术日报仪表盘 v2.2）

单文件交互式 HTML 技术日报。**六条铁律**：

0. **日期必须是今天**——发布日 = 用 `date +%F` 实时获取的当天日期，禁止手算、禁止沿用旧值或旧日报日期；`build_daily.py` 会拿系统日期校验 `date` 字段，不是今天就拒绝生成。
1. **只收昨天的信息**——信源日统一为发布日前一日，逐条核实日期，过期素材一律剔除。
2. **车本位筛选**——一切与车直接或间接相关；每条必须附「上车机会点」点评。
3. **观点只收大牛**——院士、部委负责人、车企董事长/CEO/高管、首席科学家、权威机构负责人（乘联会/中汽协/Gartner 等）的真实引文，必须附来源；禁止编造观点、禁止"业内人士"。
4. **每条资讯必须带真实可点击原文链接**，不编造 URL。
5. **板块数量灵活**——不必凑满 6 板块，也不必每板块都 4 条：按当日素材实际分布自选 **4-8 个板块**、每板块 **2-6 条**、总条数 **≥16**。方向可借鉴 6606 周情报库类目池（人工智能/机器人/通信/半导体/安全/能源/飞行汽车），但不要照搬其数量。

## 产出物

- 单文件 `<YYYY-MM-DD>-技术日报.html`，内联全部 CSS/JS，无外部依赖
- 数据同时存一份 `<YYYY-MM-DD>-daily-data.json`（便于复用/回查/生成专题）

## 触发识别

以下用户表述都应触发本 skill，且**一律生成「今天」的日报**（无论用户是否明说日期）：

- "生成今天的技术日报" / "给我生成今天的日报" / "生成今天的日报" / "今天的日报做一下"
- "生成今日科技日报" / "今天的科技事件有哪些" / "今天有什么科技新闻"
- "技术日报" / "每日技术动态" / "资讯仪表盘" / "前沿技术简报"
- 在「每日科技快报」自动化任务中要求出仪表盘版日报时

若用户明确指定了历史日期（如"生成 8 月 20 日的日报"），则按指定日期出归档版，但必须在文件名和页头标注该历史日期，且验证脚本会因新鲜度守卫提示——归档版属例外，需在回复中说明。

## 工作流（SOP）

### 1. 确定日期（必须用 shell 实时获取，不许手算、不许沿用旧值）

```bash
date +%F          # 发布日 —— 必须是今天
date -d "yesterday" +%F   # 信源日（Windows Git Bash 可用）
```

**发布日 = 今天**是硬约束：`build_daily.py` 会把 `date` 字段与系统当天比对，不一致直接拒绝构建——防止把旧日报当"今天"交付。

### 2. 分板块联网搜索（必做，不可跳过）

用 WebSearch，`freshness: d2`（近 2 天），查询必须带**昨天日期 + 板块关键词**。

**板块数量灵活（铁律 5）**：先广撒网搜集，再按当日素材实际分布收敛成 **4-8 个板块**，每板块 **2-6 条**、总条数 **≥16**。不要硬凑 6 板块×4 条；某方向当日没料就少建或不建该板块。

方向池（可增删，数量自选）：

| 板块 key | 名称 | 示例查询 |
|---|---|---|
| headline | 今日头条 | "X月X日 车企 发布 重磅" |
| frontier | 科技前沿 | "X月X日 芯片 AI 算力 突破" |
| basic | 基础研究 | "X月X日 Nature 电池 材料 论文" |
| connected | 智能网联汽车 | "X月X日 智能驾驶 座舱 发布" |
| security | 隐私安全 | "X月X日 汽车数据安全 漏洞 车联网" |
| policy | 政策法规 | "X月X日 汽车 政策 标准 法规" |
| robot | 机器人 | "X月X日 人形机器人 具身智能" |
| energy | 能源电池 | "X月X日 固态电池 快充 储能" |
| aero | 低空经济 | "X月X日 eVTOL 飞行汽车 低空" |

**筛选标准**（与「每日科技快报」一致）：
- 技术向：优先"能上车应用的技术"；不选泛行业新闻、营销稿、人事变动；
- 信息密度高、含具体数字；宁缺毋滥；
- 每条记录：标题、摘要（含数字，≤200字）、上车机会点（一句话，落到对长安/车企的价值与跟踪建议）、信源名称、信源评级（A 官方/顶级期刊、B 权威媒体、C 行业媒体）、真实原文 URL。

### 3. 搜集大牛观点（4-8 条）

用 `WebSearch` 搜 "X月X日 <领域> 院士/董事长/CEO/专家 观点 表态 判断"。
硬性规则：
- 发言人必须是**具名真实人物**且身份够格（见铁律 3）；
- 引文必须来自搜索结果原文，可浓缩但不可编造；
- 每条记录：立场（看好/谨慎/中立）、引文（标注 1 处高亮句）、姓名、头衔、场景（发布会/车展/社媒/访谈/报告）、信源、信源评级、原文 URL；
- 至少安排一对**同一议题的对撞观点**（供交锋区使用）。

### 4. 拉取 6606 七日全景（推荐，勿跳过）

6606「马良洞见·智驭未来」周情报库已按天收录近一周条目（含类目/相关度/原文）。用脚本自动生成七日全景片段，直接合并进 data.json：

```bash
python scripts/fetch_weekly.py --days 7 --picks 3 -o weekly_fragment.json
# 或一步合并进已组装的 data.json：
python scripts/fetch_weekly.py --merge data.json
```

产出 `weekly` 字段（见 data-schema.md）：近 7 天每天的收录条数、类目分布、相关度最高的 3 条精选（带原文）、每类目周趋势摘要。渲染为 **M5「七日全景」** 板块——把"每周每天的信息"直观展现出来。

> 板块与条数借鉴方向、不照搬数量：这里的每日条数/类目分布是 6606 库的真实数据，与日报自建的 4-8 板块相互独立。
> 若 6606 拉取失败，可省略 `weekly` 字段，模板会自动隐藏 M5，不影响其余板块。

### 5. 组装数据 JSON

按 `references/data-schema.md` 写一份 `data.json`（4-8 板块条目 + 观点 + 专题候选 + 技术卡 + 洞察 + weekly）。
**专题候选（topics）**：从当日条目中挑 4-6 个最值得深研的议题，每个给出 3-5 条研究大纲要点。

### 6. 构建 + 验证

```bash
python scripts/build_daily.py <data.json> "<输出目录>/<YYYY-MM-DD>-技术日报.html"
python scripts/verify_dashboard.py "<产出的 html 绝对路径>"
```

- `build_daily.py` 把 JSON 注入模板的 `<script id="tdb-data">` 数据槽，不改任何结构；
- `verify_dashboard.py` 用 Chrome headless 渲染计数，并做**日期铁律守卫**：
  发布日≠今天 / 信源日≠昨天 直接 FAIL——这是"不许出旧闻"的技术闸门；
- 同时校验板块数量（4-8 个、每板块 2-6 条、总数≥16）与 weekly 七日全景结构；
- FAIL 时按提示修正 data.json 再重新构建（最常见：JSON 语法错误、板块条数越界、观点缺 URL）。

### 7. 交付 + 专题引导

1. `present_files` 展示 HTML；
2. 回复摘要中列出：各板块条数、当日最强 3 信号、观点交锋主题、七日全景总条数；
3. **必须主动提示**：列出 4-6 个专题候选，告诉用户"回复『生成专题：XX』（可选 PPT 或 HTML）即可深研"。
   日报 HTML 的专题中心卡片内置了一键复制指令，用户也可从页面里复制。

### 8. 专题深研（用户点单后执行）

按 `references/topic-workflow.md` 执行：
- **PPT 专题**：调用长安模板风（见用户 PPT 规范：浅灰底+深藏青/青绿/橙、高密度卡片、结论落到对长安的含义），产出 8-12 页；
- **HTML 专题**：单文件深蓝科技风长页（事件脉络→技术拆解→竞争格局→对长安的含义→跟踪清单）。
两者都必须基于当日条目 + 追加 2-3 轮针对性搜索，禁止只用存量素材。

## 关键约束

- **禁止编造**：日期、数字、引文、URL 必须来自搜索结果；无法核实的用定性描述。
- **信源评级**：A=官方发布/顶级期刊；B=权威媒体（新华/人民/每经/证券时报等）；C=行业媒体。评级影响卡片盾标颜色，不许虚标。
- **雷达图**：各领域密度必须按当日真实条目数估算，不许沿用昨日数值。
- **统计条数字**（今日新增等）必须等于真实收录条数。
- 生成后用 verify 脚本兜底，不许跳过。
