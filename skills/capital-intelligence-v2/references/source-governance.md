# 数据源、冲突与时效规则

## 来源选择

按任务选择最少充分来源，不按库数量衡量研究质量。

1. 选择一个核心来源。
2. 对关键数字和高风险结论选择一个核验来源。
3. 只有问题确实涉及技术、专利、资本、政策等维度时才调用对应MCP。
4. 来源不可用时记录并降级；不要循环重试相同失败调用。

## 搜索与详情

- Search 结果用于发现候选。
- Detail、原始文档、官方公告或完整内部卡片用于建立已验证事实。
- 只有 search snippet 时使用 `evidence_level=search_snippet` 和 `review_status=candidate`。

## 冲突优先级

不存在统一的“内部永远优先”。按事实类型处理：

| 事实类型 | 优先级 |
|---|---|
| 公司内部制度、项目、内部指标 | 已审核 internal_direct 卡优先 |
| 财报、销量公告、IPO状态、政策效力 | 最新官方原文优先 |
| 用户调研 | 原始样本和明确口径优先 |
| 市场规模和行业排名 | 保留机构口径差异，不强行覆盖 |
| 技术路线 | 专利、产品发布、技术档案交叉印证 |

冲突时建立多条事实，并在 notes 中说明口径、时间和差异。

## 新鲜度

- 每个任务都声明 `data_as_of`。
- 时效性强：销量、财务、价格、IPO、政策状态、合作进展。
- 时效性中：产品配置、组织机构、投融资估值、产能状态。
- 时效性低：产业定义、历史案例、基础技术原理。

不得把库的整体更新时间当作每条事实的更新时间。

## 内部数据边界

- `internal_direct`：可以表述为公司自身事实。
- `benchmark`：只能表述为竞品或对标信息。
- `external_context`：只能表述为行业背景。
- 未知 scope 时，不得自动归类为内部事实。

## 数据缺口

以下情况必须建 gap：

- 重要金额、比例、时间或状态缺失。
- 样本量不足以计算频次、热度或人群占比。
- 同名实体无法消歧。
- 来源冲突且无法判断口径。
- 用户禁止了必要来源。
